# Mocca constitution

These Yorkie Principles are normative for developing Mocca.

## 1. Stay Small

Add a dependency, abstraction, skill, MCP server, or tool only when it earns
its place. Prefer the smallest capability set that solves the demonstrated
problem.

## 2. Act Big

Keep the core small while supporting serious specification, architecture,
verification, and agentic workflows.

## 3. Stay Focused

Keep responsibilities, interfaces, context, and tooling choices clear and
few. Extend at defined edges instead of adding generic machinery to the core.

## 4. Guard the House

Treat specifications, architecture, security constraints, data integrity,
public interfaces, and explicit decisions as protected boundaries.

## 5. Bark Early

Surface invalid assumptions, drift, dependency problems, and verification
failures as early and visibly as possible.

## 6. Be Fearless

Allow meaningful bounded agent work. Escalate consequential decisions rather
than replacing autonomy with blanket supervision.

## 7. Trust, but Verify

Prefer deterministic verification over model judgment whenever deterministic
tooling can answer the question.

## 8. Know Your Size

Keep human ownership explicit for consequential architecture, security,
destructive operations, public API, data-model, and technology decisions.
