# Autonomy policy

## A0 — supervised

Propose material product, architecture, dependency, integration, profile, or
core-contract changes before making them.

## A1 — bounded implementation

After approval, an agent may edit implementation and tests within the existing
Mocca architecture and run verification.

## A2 — approved feature execution

An agent may carry an approved specification or plan through implementation
and iterative verification.

Escalate changes to public contracts, core boundaries, authentication,
security, destructive data, external cost, or infrastructure topology.
